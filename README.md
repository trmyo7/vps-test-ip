## 测试IP能测什么，测不出什么

测试IP覆盖的是网络这一层：从你所在的位置 ping 它，能拿到延迟和丢包率；用它跑 traceroute，能看到去程路由；下载商家挂的测试文件，能验证带宽。正规商家一般会一次性给出三样东西——测试IP、Looking Glass 入口、100MB 或 1GB 的测试文件，Vultr 这类大厂每个机房都是这个配置。三样凑齐，线路的大方向基本就清楚了。

测不出来的也有两样。一是回程路由：你 ping 测试IP，数据包走的是去程方向，服务器往回发的路要靠 Looking Glass 里的 mtr 或 traceroute 才能看到，而回程恰恰比去程更重要，因为服务器发回来的数据量通常远大于你发出去的请求。二是机器本身：IO 性能、超售程度、CPU 是否缩水，测试IP完全反映不了，这些只能等开通后跑脚本验证。

## 拿到测试IP后的 5 步实测流程

工具都是免费的，全程大概十几分钟，建议按这个顺序做：

1. **先确认IP没被墙。** 用 ping.pe 这类多地点工具扫一遍：国内节点全部超时、海外正常，基本就是被墙了，后面的步骤都不用做了。
2. **看大陆三网的延迟和丢包。** ping.pe 会从全球多个节点连续 ping，实时显示平均延迟和丢包率。别只看总平均值，逐个看电信、联通、移动的节点，三家都干净才算干净。
3. **用 tcping 测你本地到测试IP的延迟。** 普通 ping 走 ICMP 协议，运营商做 QoS 时可能给 ICMP 开小灶，结果比真实体验好看。tcping 走 TCP 协议，更贴近实际使用。如果你买 VPS 只是自己挂代理用，这一步测出来的数字比前面所有数据都重要——因为它就是你以后真实走的那条路。
4. **查去程路由。** itdog 的 traceroute 页面能让国内多个机房同时追踪到测试IP的路由，沿途每个节点的 IP、位置、延迟都看得到。去程是参考项，主要用来认线路。
5. **晚高峰下载测试文件，再看回程。** 白天跑得飞快不算数，晚上八九点再测一轮：直接下载商家给的 100MB 测试文件，看速度能不能跑满标称带宽；回程路由去 Looking Glass 里跑 mtr 或 traceroute，看服务器回国内走的是什么路。

## 结果怎么读：几个关键数字和IP段

判读主要看四组数字，对照下面这些基准就够了。

**ping 基准**：国内机房几十毫秒；日本、韩国、新加坡一般几十到一百多毫秒；美国、欧洲普遍 200ms 起步。同条件下延迟越低越好，但 ping 低不代表网速快。

**丢包率**：高于 5% 就可以判定网络状况差。晚高峰零丢包，比白天速度跑得高有价值得多——白天快是应该的，晚上不崩才说明线路真的行。

**路由里的IP段**：看到 59.43.*.* 是 CN2 线路，去程回程都有就是 CN2 GIA，只有去程有是 CN2 GT；全程都是 202.97.*.* 就是普通 163 骨干网。商家页面写着“三网优化”但路由里全是 202.97 的，说明只优化了去程，这种要留个心眼。

**tcping 和 ping 的差值**：tcping 比 ping 高出一大截，说明 ICMP 被特殊照顾了，以 tcping 的数字为准。

测速方向也有讲究：做站或者挂代理，实际占用的都是服务器的上传带宽，所以测速结果里上传速度比下载速度更值得关注。换算别搞混，100Mbps 的实际下载上限是 12.5MB/s，商家标的数字除以 8 才是 MB/s。

## 几个常见问题

**测试IP的 ping 多少算正常？**
按距离估：国内机房几十毫秒，日韩新加坡一百毫秒上下，美欧 200ms 往上。明显超出这个范围，或者同一节点忽高忽低，重点查丢包。

**为什么 ping 很低，用起来还是卡？**
先查丢包，再看回程。ping 只反映 ICMP 的往返延迟，网络拥塞时路由器会按策略丢包，而且 ICMP 可能被优先放行，所以 ping 好看不等于 TCP 流量顺畅。tcping 加回程 mtr，两个都过关才算过关。

**怎么判断测试IP被墙了？**
用 ping.pe 看全球节点：国内全部超时、海外正常，基本可以确认；个别节点偶发丢包属于正常波动。

**测试结果能管多久？**
线路会变。商家调整路由、你所在省份晚高峰拥塞，都会让旧数据失效，所以测试要尽量贴近下单时间，开通后再自己复测一遍最保险。
